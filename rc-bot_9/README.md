# Бот учёта заданий РЦ — первая версия

Считает прогресс резидентов по программе не в заданиях, а в **единицах**:
один пример, вопрос или граница = одна единица. Всего в основной программе
**224 единицы** — от этого и пляшет вся арифметика.

## Как пользоваться

Внизу экрана постоянные кнопки, команды печатать не нужно:

📋 **Задания** — резидент → задание → сфера → отметить примеры
🔧 **Техничка** — записать пункт для смены и закрыть выполненный
📊 **Сводка** — кто отстаёт, кто спешит, кто без задания
👥 **Смена** — состав смены и что сделано за день
📄 **Таблица** — выгрузка CSV, открывается в Excel и Google Таблицах

## Внесение отчётов МГ

В «Заданиях» есть кнопка **📥 Внести отчёты МГ**. Вставляешь текст из чата
как есть — хоть одну малую группу, хоть переписку за неделю.

Бот понимает привычную нотацию: `сф6 пр1, пр2`, `2 сфера 1-4 примеры`,
`9/2, 9/3`, `закрыл задание`. Всё, помеченное «переписать» или ❌,
не засчитывается.

Показывает разбор и ждёт подтверждения — записывает только после кнопки.
Строки с незнакомыми именами пропускаются: бот работает только с теми,
кто заведён в базе.

Команды для руководителя: `/add`, `/tek`, `/data`, `/vypisat`.
Ещё есть `/kartochka` — подробная карточка резидента.

## Техническая информация

Отдельный список, не связанный с заданиями. Добавить можно в любой момент:
«Добавить» → написать текст. Несколько пунктов — с новой строки, каждый
станет отдельным.

Пункт не исчезает, пока его не закрыли. Висящие два дня и дольше
помечаются ❗️ — видно, что передаётся из смены в смену.

## Две программы

**Основная** — 13 заданий, 224 единицы, 180 дней.
**Срыв** — 11 заданий, 133 единицы, около 29 дней по нормативам.

Единица — один пример, вопрос или граница. Прогресс считается в них,
потому что задания очень разные по объёму: в Иллюзиях 36 примеров,
в Сценарии срыва один.

## Как считается «отстаёт» и «спешит»

Прошло 40% срока — ожидаем 40% программы. Факт сравнивается с ожиданием:

- 🔴 отстаёт — минус 7% и больше
- 🟡 по графику
- 🟢 спешит — плюс 7% и больше

## Добавить резидентов

Одним сообщением, по строке на человека:

```
/add
Умид 13.03
Шерзодбек 14.03
Дилшод 12.08 срыв
```

Год можно не писать. Выписка ставится автоматически: +6 месяцев,
для программы срыва +1 месяц. Поправить потом — через `/data`.

Список с доски уже готов в `scripts/import-board.js`:

```bash
node scripts/import-board.js
```

## Деплой на Railway

1. Залить проект в **приватный** репозиторий GitHub. Файл `.env` не заливается —
   он уже в `.gitignore`.
2. На railway.app: **New Project → Deploy from GitHub repo**, выбрать репозиторий.
3. Вкладка **Variables**, добавить три переменные:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | новый токен от BotFather |
   | `ADMIN_IDS` | `6996710979` |
   | `STAFF_IDS` | `6996710979` (потом добавить консультантов через запятую) |

4. **Создать volume.** ⌘K → *New Volume* → выбрать сервис →
   mount path: **`/data`**

   ⚠️ Не `/app/data`. Там лежит `tasks.json` со справочником заданий,
   и пустой volume перекроет эту папку — бот упадёт при старте.

   Путь к базе определяется сам: если папка `/data` есть, бот пишет туда.
   Переменную `DB_PATH` задавать не нужно.

5. Redeploy. В логах должно появиться:

   ```
   База данных: /data/db.json
   Бот @имя_бота запущен
   ```

6. Написать боту `/start` в Telegram.

### Если не запускается

| В логах | Что делать |
|---|---|
| `Нет переменной BOT_TOKEN` | не добавлена во Variables |
| `401 Unauthorized` | токен неверный или отозван |
| `База данных: /app/data/db.json` | volume смонтирован не туда |
| Бот отвечает «Нет доступа» | твоего ID нет в `STAFF_IDS` |

### Обновление кода

Push в GitHub → Railway передеплоит сам. Данные на volume остаются.
При передеплое бот на минуту недоступен — volume не позволяет двум
деплоям работать одновременно.

Подключается вторым шагом, когда люди привыкнут открывать бота.

## Про данные

Доступ строго по списку Telegram ID в `.env`. Это данные о людях в реабилитации —
в боте только имена и прогресс по заданиям, без диагнозов, лекарств и медицинских
записей. Лист лекарств, когда дойдёт очередь, стоит держать с отдельным доступом.

## Демо-бот для показа

Чтобы показать бота кому угодно, не открывая настоящую базу.

1. У @BotFather сделать **второго** бота — свой отдельный токен.
2. На Railway: **New → Deploy from GitHub repo**, тот же репозиторий,
   Root Directory `rc-bot_2`.
3. Variables:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен второго бота |
   | `DEMO` | `1` |

   `ADMIN_IDS` и `STAFF_IDS` в демо не нужны.
4. Volume **не подключать** — пусть данные сбрасываются при каждом деплое.

В демо-режиме заходит любой, все резиденты вымышленные («Резидент А» и так далее),
картина подобрана так, чтобы были видны все три цвета светофора.
При первом запуске данные создаются сами.

⚠️ Никогда не ставить `DEMO=1` на рабочего бота: это откроет доступ
к настоящим именам резидентов всем подряд.

## Где хранятся данные

Файл `db.json` на volume: путь `/data/db.json` на Railway, `./data/db.json` локально.
Запись идёт сразу после каждого действия, поэтому при внезапном падении
теряется максимум последнее нажатие.

Переживает: падение бота, перезапуск, передеплой, перезагрузку контейнера.
Не переживает: удаление volume или пересоздание сервиса.

### Резервная копия

`/backup` — бот присылает файл с полной базой. Раз в неделю стоит сохранять.

Восстановление: прислать боту этот файл с подписью `restore`. Бот покажет,
сколько в нём резидентов, и спросит подтверждение — текущая база будет
полностью заменена.

Файл копии содержит имена резидентов и их прогресс. Хранить в личных
сообщениях, не в общем чате.

## Смена и авторство

Персонал задаётся переменной `STAFF` на Railway:

```
STAFF=Юра:6996710979, Лена:111222333, Шохрух:444555666
```

Формат — `имя:telegram_id` через запятую. Что это даёт:

- указанные ID автоматически получают доступ, отдельный `STAFF_IDS` не нужен
- все отметки подписываются именем, а не ником из Telegram
- никто ничего не выбирает вручную

ID узнаётся у @userinfobot. Можно писать имя без ID — тогда человек
выберет себя в боте сам, один раз.

Переменная перечитывается при каждом запуске, так что добавить или
поменять человека — это правка переменной и Redeploy. Уже привязанные
не слетают.

Команда `/kto` показывает свой ID и всю таблицу привязок.

На экране «Смена» имена переключаются нажатием:

- первое нажатие — человек на смене
- второе — он консультант №1
- третье — снять со смены

Там же видно, сколько единиц принято за сегодня и кем.
В карточке резидента у каждого задания подписано, кто принимал последним.
