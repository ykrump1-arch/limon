# Бот учёта заданий РЦ — первая версия

Считает прогресс резидентов по программе не в заданиях, а в **единицах**:
один пример, вопрос или граница = одна единица. Всего в основной программе
**224 единицы** — от этого и пляшет вся арифметика.

## Что уже работает

| Команда | Что делает |
|---|---|
| `/mg` | Приёмка. Резидент → сфера → отметить принятые примеры |
| `/today` | Сводка на смену: кто без задания, кто отстаёт, цифры за неделю |
| `/card` | Карточка резидента: прогресс, история заданий, прогноз |
| `/mgday` | Отметить: МГ прошла / сокращённая / отменена |
| `/stats` | Реальные цифры по дому за 30 дней |
| `/add Имя` | Добавить резидента (только руководитель) |

## Ключевые решения

**Приёмка не привязана к МГ.** Расписание плавает, поэтому кнопка доступна
всегда, а консультант отмечает контекст: МГ / КС / индивидуально. Через месяц
видно, какая доля программы реально закрывается вне малой группы.

**Прогноз считается от факта, а не от плана.** Не «просрочил на 5 дней», а
«за последние 30 дней темп 0,4 ед/день, при таком темпе не успеет 60 единиц».
Устойчиво к отменам и переносам.

**Закрыл — сразу предлагает вынести следующее.** Пауза между заданиями —
самая частая потеря времени в бумажной схеме.

**Чек-лист формата при приёмке.** У заданий шесть разных форматов, у Бессилия —
15-шаговая цепочка. Бот показывает нужный, чтобы разные смены принимали одинаково.

**Первый месяц — только измерение.** Никаких оценок консультантов, никакой
статистики по людям. Сначала честные цифры, потом всё остальное.

## Запуск

```bash
npm install
cp .env.example .env      # вписать токен и ID
npm start
```

Демо-данные для показа руководителю:

```bash
npm run seed
```

## Деплой на Railway

1. Залить проект в **приватный** репозиторий GitHub. Файл `.env` не заливается —
   он уже в `.gitignore`.
2. На railway.app: **New Project → Deploy from GitHub repo**, выбрать репозиторий.
3. Вкладка **Variables**, добавить три переменные:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | новый токен от BotFather |
   | `ADMIN_IDS` | `6996710979` |
   | `STAFF_IDS` | `6996710979` (потом добавить консультантов через запятую) |

4. **Создать volume.** ⌘K → *New Volume* → выбрать сервис →
   mount path: **`/data`**

   ⚠️ Не `/app/data`. Там лежит `tasks.json` со справочником заданий,
   и пустой volume перекроет эту папку — бот упадёт при старте.

   Путь к базе определяется сам: если папка `/data` есть, бот пишет туда.
   Переменную `DB_PATH` задавать не нужно.

5. Redeploy. В логах должно появиться:

   ```
   База данных: /data/db.json
   Бот @имя_бота запущен
   ```

6. Написать боту `/start` в Telegram.

### Если не запускается

| В логах | Что делать |
|---|---|
| `Нет переменной BOT_TOKEN` | не добавлена во Variables |
| `401 Unauthorized` | токен неверный или отозван |
| `База данных: /app/data/db.json` | volume смонтирован не туда |
| Бот отвечает «Нет доступа» | твоего ID нет в `STAFF_IDS` |

### Обновление кода

Push в GitHub → Railway передеплоит сам. Данные на volume остаются.
При передеплое бот на минуту недоступен — volume не позволяет двум
деплоям работать одновременно.

## Чего ещё нет

- Передача смены и техническая информация
- Лист лекарств
- Авто-сборка сменного отчёта
- Отчёт МГ текстом в привычном виде

Подключается вторым шагом, когда люди привыкнут открывать бота.

## Про данные

Доступ строго по списку Telegram ID в `.env`. Это данные о людях в реабилитации —
в боте только имена и прогресс по заданиям, без диагнозов, лекарств и медицинских
записей. Лист лекарств, когда дойдёт очередь, стоит держать с отдельным доступом.
